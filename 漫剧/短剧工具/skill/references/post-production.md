# 剪辑、配乐与交付

本地成片使用 `tools/audio/assemble.py`；这份规范供剪辑、总导演在合成、换 BGM 和交付文件时读取。用户当前要求与已批准范围优先。技术检查在内部完成，复用原有成片验收，不新增重复确认。

## 时间线和声音完整性

- 剪辑时间线绑定已采用源文件的 SHA、帧率、总帧数和保留帧范围。对白字幕与音画使用同一时间线；不得只剪视频、直接拼接已缩短的音轨，或按 ASR 序号硬配原台词。
- 有无 EDL 都采用定长、48 kHz 无损 PCM 中间音轨；按保留帧时长补齐/截齐，并重建连续样本时间戳。每段仅测量后施加常量增益，最终整集再统一响度处理。逐段动态 loudnorm 不能作为拼接前的默认流程。
- 整集响度滤镜之后仍须按总视频帧时长定长音轨：重采样至 48 kHz，补齐/截齐至 `round(总帧数 / fps × 48000)` 个样本并重建样本时间戳，再编码 AAC。不能因为输入 PCM 已定长就省略最终核对，也不能放宽尾部容差掩盖滤镜新增的尾长；对白偏移另用实际连续对白窗口检查。
- 拼接前验证每段与拼接结果的解码样本数；不符就停止交付。全静音片段保留对应长度，不凭空加入人声；整集全静音不能宣称达到对白响度目标。
- 无对白的环境或拟音空镜不必抬到对白响度。确认实际没有人声后，可在 EDL 对应片段写入 `audio: {target_lufs: -30, reason: "该镜实际只有关门及环境声"}` 等有依据的目标；默认对白目标仍为 -16 LUFS，真峰值限制、恒定增益与样本计数检查不变。实际目标和增益写入交付报告，不能把低响度当作全静音。
- 分别核对视频帧数/视频流时长和容器时长。AAC 尾部允许至多两个 1024 样本帧的填充；该容差只用于容器尾部，不豁免视频少帧、对白偏移或逐段累计误差。
- 最终响度滤镜的目标不能代替实际 AAC 峰值。当前合成器在整集响度后以 192 kHz 瞬态限制器控制峰值，关闭自动补偿增益、补偿前视延迟，再定长 48 kHz 浮点 PCM，并分别记录 PCM 与 384 kbps AAC 的实测响度/峰值。若编码后仍超限，保留失败记录并定位处理环节，不单纯放宽指标；滤镜、重采样或编码方式变化后重核对白时间位置。
- 若限幅后的 PCM 响度低于原验收下限、且实测真峰值仍有余量，可按该余量作一次常量增益补偿并预留 AAC 编码余量；补偿后重核定长样本和最终 AAC 响度/峰值。记录补偿前后测量与实际增益，余量不足仍按原指标拦截，不用调低目标或放宽容差代替修复。
- 实际音画同步仍要听看，自动样本计数只能拦截长度问题。波形相关可辅助测量后期引入的偏移，不能证明模型口型或音色正确。BGM/停顿使相关性偏低时保留原失败记录，在连续原对白区间补核并写明原因，不降低阈值凑通过。

## 选曲与交付用途

- 选曲时先利用已知发布平台和用途核查授权范围，再推荐或混入待发布成片。公开收听、热门榜、搜索结果或同名收录不是本次视频使用许可的凭据；普通展示也不能直接推导许可。
- 选曲前可运行 `tools/audio/delivery_checks.py --project <作品> --music <候选曲路径> --purpose public-release`。曲库 `usage_scope` 记录已核实的 `platforms` 和 `uses` 列表；与当前平台/用途不匹配则拦截。`*` 仅在证据确实支持相应范围时登记，不能自动补齐来绕过检查。
- 可先制作明确的本地试听版；报告注明授权待核实。缺少发布许可时，不将试听素材作为可直接上传文件交付。
- 用户表示要上传或发布后，在 `project.json.delivery_intent` 记录 `purpose: public-release`、已知 `platform`、`use` 及来源；沿用已有回答，不重问平台或用途。此字段表示目标，不代表已经获得授权或已经发布。
- `assemble.py` 默认同时检查 `publish` 和 `delivery_intent`。任一表明发布，缺少已核实音乐授权或本地标识要求就拦截。授权登记应包含实际文件、来源、许可及适用范围、署名、SHA 和可读的本地证据；不能伪造 `license_verified`。
- `--purpose preview` 显式导出试听版；`--no-visible-ai-label` 仅可在本次预览使用，不更改项目默认值。它只控制本工具自行叠加的画面文字，不能当作移除第三方来源信息的通用命令。
- 交付用于上传的文件前，运行 `tools/audio/delivery_checks.py --project <作品绝对目录> --video <成片路径> --purpose public-release`，核对实际视频/SRT 指纹、技术报告、当前配乐证据和标识。即使旧报告写 `publication.status=complete`，也只证明本地文件写出，不能代替发布条件。

## 验收和版本

- 新报告用 `delivery.status=complete` 表示文件已生成，用 `release.status` 区分 `local_preview_only` 与 `technical_checks_passed_review_required`。技术通过始终保留实际听看要求，不自动写成用户通过、授权已取得或已在平台发布。
- 实际检查字幕位置、原话、额外人声、发声人物、音色、口型、空间及动作完成；首中尾检查不能替代关键发声/动作区间。音轨完全相同且剪辑时间线相同时可复用已有同步证据，如实注明沿用，不冒充本次新试听。
- 用户已接受的局部静音、快语速或动作偏差只适用于具体版本。修改保留原片、原音轨、剪辑范围、核验结果和采用来源。能在授权内局部修复的直接处理，不默认付费重新生成。
- 输出新版本，不覆盖源视频或既有 MP4/SRT/报告。报告最后写出并绑定媒体指纹。变速同时处理音频；转场重算时长；字幕路径正确转义，中文 Windows 字体使用已核验的 ASCII 路径。
- AI 标识开关是本工具的制作要求。普通 comment 元数据不等于已验证满足所有平台的隐式标识标准；平台发布声明在实际发布环节按已有要求处理。
