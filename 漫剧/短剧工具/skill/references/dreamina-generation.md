# 即梦生成与任务管理

## 使用前

本阶段的命令参数已按打包时本机 CLI --help 核对；运行环境可能不同，先检查 dreamina version 与相关子命令 --help。实际生成前检查登录和 user_credit，不在只写提示词时登录。
缺工具时报告安装需求，不直接下载并执行远程安装脚本。登录按当前帮助由用户完成或使用受支持的本地流程，不将凭证写入项目。
模型/分辨率/比例由 project.json 决定。原包偏好可继续配置，但不要因会员模型不可用自动换更贵模型。实际生成消耗积分，在用户授权范围和预算内提交。

## 准备与提交

命令和可执行示例见 [CLI使用](dreamina-cli.md)。新独立资产用 text2image；衍生资产用 image2image（参数 --images）；视频默认 multimodal2video（重复 --image）。后者至少需一张图或视频。

使用 scripts/prepare_submission.py 从提示词文件与附件列表生成 request.json。脚本只准备不提交，避免 shell 拼接和图号错误。随后 scripts/submit_task.py 默认预览，传 --execute 才提交。由 Agent 在已授权生成范围内执行，不需要为每条自动插入一次确认。

每次请求使用独立 attempt 目录，脚本先写 submitting 日志再调用 CLI，响应保存在本地。相同目录不重复执行；超时或没有任务ID标 unknown，先 list_task 找回。不把请求摘要误当服务端幂等保证。

## 查询与下载

使用 submit_task.py --query 查询已登记ID，一次调用只查一次并保存原始响应，Agent 解析实际状态。按工作流参考中的有限等待窗口轮询；成功/失败/取消即停止，超时保留任务，不重新提交。
成功响应取得结果后，用 query_result --download_dir 下载至任务目录，检查媒体可解码，再复制到计划路径。JSON响应结构可能变化，无法判定状态时报告原始错误，不捏造完成结果。
遇到未知提交，可用 --recover-id 经 list_task 核对后补登记。完成或明确失败后，以 --mark-status 更新本地状态；此标记由 Agent 根据响应证据使用，不自动猜测。

## 生成质量

资产查看实际图片；视频检查时长、音轨、开头、中间与尾部画面。尾帧作为参考能改善连续性，但不是首帧逐像素保证。严格首尾图需求见 frames2video 当前帮助。
平台拒绝、额度不足或要求Web授权时，停止该任务并说明恢复步骤，不自动反复改名重试。
