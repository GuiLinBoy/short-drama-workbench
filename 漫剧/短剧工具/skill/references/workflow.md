# 阶段与恢复

| 阶段 | 输入 | 输出与通过条件 |
|---|---|---|
| ingest | 原文及指定章节/字符范围 | 大纲.txt、读取进度.json、assets.json、资产详情；记录来源，范围无跳读 |
| design | 已抽取资产、项目风格 | 风格素材.md、各资产 .prompt.txt；关键外观一致，未混入无关元素 |
| storyboard | 故事、资产、时长 | 文字分镜.txt、clips.json；时间段不重叠，资产与承接来源可解析 |
| prompts | 分镜 | 视频_Clip00001.prompt.txt 等；剧情、时长、动作与分镜一致 |
| assets | 资产提示词、已有可复用图 | 图片、任务记录；逐张查看图像，确认身份、形态、背景及清晰度 |
| clips | 通过检查的图片、视频提示词 | 视频、首帧承接记录、必要尾帧；逐条查看抽帧并核对音轨/时长 |
| assemble | 按 clips.json 排列的已通过视频 | 成片.mp4、检查报告；播放完整可解码，尺寸帧率一致，真实时长达标 |
| publish-kit（可选收尾） | 已通过的定稿成片、无字幕源帧、授权记录 | 平台发布文案（标题/简介/标签/AI 声明与音乐 CC 署名）、横（16:9）竖（3:4）双封面，以及按用户要求清理未采用旧版本（保留定稿指纹与清单） |

有参考图时使用 multimodal2video。用户明确指定纯文本视频时可使用 text2video，但要记录缺少视觉锚点对一致性的影响，不伪造参考图。

只有实际存在 continue_from 的 clip 依赖其前置 clip 完成；其他片段可独立处理。跨集也只按真实依赖串行。默认生成并发上限为 1，用户配置上限与实际账户限额取较小值；不要将旧包的“固定最多3个”视为永久平台限制。

资产复用比较身份/形态、风格版本、提示词内容摘要与图片验收状态。上游变化只使受影响的下游产物失效。复用已有文件前检查是否可读、有内容且与记录匹配。

尾帧归生产者集目录，首帧承接记录归消费者集目录。跨集来源显式记录 EP 与 clip，不以目录排序猜测故事对应关系。尚未生成上游视频时只写预期动作；实际提交前观察真实尾帧，再补充可见的站位、朝向和动作，不假装已见到画面。

multimodal2video 的尾帧是参考图，并不保证逐像素锁定第一帧。严格首尾帧需求可在用户范围内选择支持对应输入的模式（如 frames2video，需要真实首、尾图），同时检查该模式能否兼容角色参考需求。

## 保存与任务恢复

单文件先写同目录临时文件，校验通过后 os.replace。多个关联文件采用版本目录 snapshots/<revision>/，全部校验后原子切换一个 current.json 指针；不要宣称多个 rename 是一个事务。既有 TXT 项目可在暂停下游读取的维护阶段迁移，保留旧版备份。

进度在对应批次资产/大纲成功提交后推进；记录输入 SHA256、字符起止（左闭右开）、读取到的位置与已提交位置。文件变化时不沿用旧 offset。

任务记录由 [即梦生成指南](dreamina-generation.md) 脚本保存请求摘要、响应和任务 ID。提交超时或无法解析 ID 时状态为 unknown；先查 list_task 找回任务，不直接重新提交。只有已明确失败且确定重试范围时才创建新 attempt 目录。

已知任务 ID 用 query_result 查询；默认每次查询间隔 30 秒，总等待窗口 20 分钟。完成/失败/取消立即停止；超时保留任务 ID，后续继续查询，不认定生成失败。查询临时错误最多重试两次，未知响应交给 Agent 检查，不凭猜测字段认定成功。
