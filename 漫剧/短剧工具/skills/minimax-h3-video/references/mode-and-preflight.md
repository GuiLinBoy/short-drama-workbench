# 模式、素材职责与准备核对

适用：本项目当前 CompShare H3 适配器。参考 Higgsfield 的“先确认模式和输入角色、按模型核对字段”方法，不导入其 CLI、模型别名、价格或账号权限。

## 1. 先分清三层信息

| 层 | 事实来源 | 不能混入 |
|---|---|---|
| H3 提示词格式 | MiniMax 官方基础/全参考指南 | 其他模型的短提示词上限、说话人语法 |
| 渠道与本地实现 | CompShare 文档、已核验的 `h3_task.py`、受控入口 | Higgsfield 的 `minimax_h3_max` 等模型名、参数范围和默认值 |
| 本片执行规格 | 用户当前要求、实际批准的请求/画布版本、预算和限额 | 旧片额度、通用默认值对已审版本的覆盖 |

本地默认：`model=MiniMax-H3`、`resolution=768P`、`use_context_ir=false`、4–15 整数秒；未获新批准不切 Lite、不超分、不使用 `--allow-long`。这些是本地当前选择，并非声称所有平台的 H3 都有相同能力。修改默认文档不改写已有请求。

## 2. 输入模式与素材职责

| 目标 | 模式/素材槽 | 写作重点 |
|---|---|---|
| 无素材，从文字建立场景 | T2VA，三段式 | 完整可见/可听时间线 |
| 开头严格对齐一张图 | I2VA，`first_frame`，三段式加对齐 | 首帧实际状态及之后的运动，不再冲突地重设开场 |
| 开头和结尾分别对齐图 | FL2VA，`first_frame` + `last_frame` | 两端之间可实现的动作路径，不只各描述一遍 |
| 结尾落到指定图 | L2VA，`last_frame` | 合理前置状态并收拢到尾帧 |
| 保留角色/场景，另定镜头和动作 | Ref2VA，`reference` 等参考槽，六段式 | 身份与服装来源、空间/光线来源、具体镜头构图各自分开 |

当前适配器不允许首尾帧槽与普通图片/视频/音频参考槽混用。全参考可以将上一段尾帧作为普通参考并在文中声明开场锚点，但这不是严格 I2VA，也不保证首帧逐像素复刻。改用严格首帧时必须重新检查能否保留所需身份/声音输入，并重审请求。

### 素材只负责明确指定的属性

- 人物图：身份、发型、服装；不自动继承定妆照的背景、全身构图或站姿。单镜只用当前形态、清晰单人图；不要为了凑“4–5张”上传无关参考。
- 场景图：空间布局、家具和光线；镜头景别及位置写在正文，不要求每镜复制场景参考图的机位。
- 尾帧：上一段**实际**结束状态；必须查看并保存真实指纹，预计描述不能充当已核对状态。
- 音频：写明是声线参考还是要求复制内容；声线参考不等于原声复制或精确克隆。约4秒是本项目社区经验建议，非跨渠道通用硬上限。
- 视频：明确参考动作、镜头还是声音；参考视频自带音轨也会输入模型，只参考视觉时先按批准范围准备去音轨的新版本。

`fully_preserved` 配合限定范围使用：例如“保留身份和服装，姿态与构图由镜头说明决定”，不把“完全保留人物外观”误写成“连背景与机位都原样复制”。场景中静态布局保持，镜头按剧情改变；确需转移/改变属性时按官方标记和用户批准写明。

## 3. 提示词压缩顺序

先删重复形容词、重复外貌、无关背景、同义禁令和无法拍到的解释，再合并相邻的重复状态。**不删除**已审台词、说话人对应、开口/闭口时段、镜头切点、空间轴线、道具状态和关键承接。

不硬凑350–500个英文单词，也不将 Higgsfield 的通用“约200 tokens”建议当作 H3 多人对白限制。以信息不冲突、时长可执行、适配器校验为准；当前底层检查映射后提示词最多7000字符，这不是目标长度。

## 4. 离线准备后逐项核对

1. 模型和渠道是否匹配本片批准；`MiniMax-H3` 不与其他平台的 `minimax_h3` 字符串互换。
2. 素材槽和提示词模式一致；图/视频/音频各自编号连续，源标签全部映射，参考职责无冲突。
3. 请求的 `duration`、`ratio`、`resolution`、`mute_audio`、`use_context_ir`、`skill_id` 与本片规格一致；关闭 Context-IR 时不传 `skill_id`。
4. `warnings` 全部解决；不能手改请求消除警告。出现供应商自动修正/降级，明确记录实际值，不能拿请求值冒充交付值；不合规格先报告。
5. 请求/参考素材/批次/attempt 对应当前画布版本，预算计算包含输出、参考视频和 Context-IR；默认值不能覆盖已批准的特殊规格。

不为核对而自行登录、查询账户或试生成。已有能力资料不足时先标“待核实”，由获准执行步骤再核对；任何能力探测都不等于生成授权。
