# MiniMax H3 漫剧视频

## 范围与执行边界

- 默认渠道是本项目 CompShare 适配器；Higgsfield 仅参考其 skill 的写作和参数分层方法，不安装其 CLI、不转接服务，不将其参数当作本渠道能力。
- 用户的当前要求和本片已批准规格优先。默认视频为原生 `768P`；`480P`、超分、换模型及新返工均须符合本片实际授权，不继承旧片额度。
- **当前 Codex 制作统一使用 `tools/codex_cli.py --project-scope <作品绝对目录> h3 ...`。** `scripts/h3_task.py` 是底层实现，不直接用于真实制作来绕过工作区、费用、审核或就绪检查；详见 [接口与任务](references/api-and-tasks.md)。
- 提示词编写及离线准备不需要读取凭证。联网动作由受控入口在检查授权后读取凭证；不查看、输出或复制认证文件、密钥、Data URL 或 base64。
- `unknown` 保持原占用，不自动重发、不新开 attempt。并发未满或请求具备幂等键都不构成重发授权；新请求、内容变化和返工先核对相应画布版本及费用范围。

## 必须保留的提示词规则

1. **中文正文，技术标记原样。** 动作、构图、风格、光线和声线写中文；保留字段名、素材标签、`<Subject N>`、`[Shot N]`、`(S1)`、`<d>[Chinese]`、`fully_preserved`、`N/A` 等技术语法。历史英文示例仅参考结构，不自动将新稿翻回英文。
2. **按输入选结构。** 全参考模式用 `subject_definitions` → `summary` → `retention_analysis` → `detailed_description` → `overall_soundscape` → `non_diegetic_music`；基础文生/首尾帧模式用三段式及所需对齐指令。不混用首尾帧槽与参考素材槽。
3. **每份素材只承担写明的职责。** 人物图提供身份/服装，场景图提供空间/光线，音频提供声线；具体姿态、构图和动作由镜头描述决定。普通参考图及全参考中的尾帧锚点不保证逐像素锁定首帧。
4. **精简重复，保留执行信息。** 人物定义只写辨识特征和素材来源，镜头正文写空间、动作、运镜与声音的变化；不要每段重述完整外貌。保留已批准台词、说话人、时间线和连续性，不套用通用“200 tokens”限额，也不为凑字数扩写。
   **每次生成请求独立、自包含。** 模型不记得上一段：本段实际可见人物均须明确身份及本次参考来源，逐一交代说话/不说话、声音绑定、开场站位朝向与手持物、空间和衔接终态。所需图片、真实尾帧和已定音色必须随本次请求实际上传。不能只写“人物同上”“沿用上次声音”“承接上一段”，也不能把工作流里的衔接报告当作模型已经收到的内容；引用文件标签时同时说明它在本段提供的具体状态。只在画外的人明确方位及是否发声，不为凑人物表上传无关角色。
5. **素材编号由工具映射。** 源稿写 `[C00001-A]`、`[S00001]` 等稳定标签；不要手写 `<Picture N>`。承接用的真实尾帧按现有适配器约定放第一个附件，且摄影须实际查看后才核对承接句。
6. **对白保持逐句可执行。** 只有会出声的角色按本段开口顺序分配 `(S1)`、`(S2)`，段内不变；`<Subject N>` 是视觉主体编号，两者不必一致。`<d>` 内只放语言标签和已批准原话，动作和声线写在外面；不说话的人及停顿区间明确闭嘴。不能擅自给已审台词增添语气词。
7. **时长与复杂度以可实现为准。** 当前本地制作默认每次 4–15 整数秒，推荐 1–2 个镜头、每镜不超过 3 个重要角色、2 个动作意图和一种运镜；这是本地复杂度控制，不是所有渠道的统一能力上限。语速只作估算，实际生成后核对漏词、抢话、口型和片尾截断。
8. **声音分层。** 对白写在对应镜头，具体环境/动作声写 `overall_soundscape`；配乐通常 `non_diegetic_music: N/A` 后期统一处理，真正旁白不交给 H3。必要的禁字幕、禁额外人声约束保留，用简短中文写清，不堆重复否定句。

## 工作流程

角色首次开口视频通过后执行 [音色收尾](../../tools/VOICE_CLOSEOUT.md)，同轮提取、登记并送原声音节点确认；后续该角色对白实际引用已通过样本。具体状态、短样本处理与拦截条件由该文档统一维护。

1. 按 [状态读取与衔接](../../tools/SHOT_CONTEXT.md) 读取当前配置、清单、审核与上下段实际素材，明确上段留下什么、本段怎么接、给下段留下什么；缺项先补齐。再选择严格首帧、身份参考或连续尾帧；独立起幅也说明依据。
2. 按所选模式写版本化中文提示词。风格和光线基准复用一次，变化写在对应镜头；承接未产生时只标预计状态，不伪造真实观察。
3. 经受控入口离线 `prepare`，核对请求中的模型、模式、素材编号/用途、整数时长、分辨率、声音与 Context-IR；逐条解决 `warnings`，不手删警告。正式请求才是送审依据，源稿不替代实际请求。
4. 总导演内部完成 [13 组自动检查与 6 项专业复核](../../tools/H3_EXECUTION_CHECKS.md)，再送既有画布视频提示词节点；按用户偏好不单独送分镜图片提示词。共用基准和未改内容复用，不为内部复核再确认。实际视频和成片沿用已有验收节点。参数和执行证据备查，费用或效果偏差明确提示。
5. 仅在本片创作与费用批准、任务范围和受控就绪均匹配时提交一次。查询/下载也核对操作授权；会话结束不会自行启动后台轮询，不能宣称已配置常驻服务。
6. 实际听看视频，按发声区间逐句核对白字、说话人、音色和口型，检查首中尾身份、站位及关键动作的完成状态。ASR 不能替代听看，关门声不能证明关严。失败时先诊断实际输入和媒体，按 [坑与对策](references/pitfalls.md) 收口；不得以 skill 建议替代对应返工授权。用户接受后同轮同步采用与视频指纹。

## 依据与限制

- 结构依据 [MiniMax 官方 H3 skill](https://github.com/MiniMax-AI/MiniMax-H3/tree/main/skills/h3-prompt-writing)；中文正文是本项目用户要求，不声称官方已对中文正文效果作保证。
- 渠道能力依据 [CompShare H3 文档](https://www.compshare.cn/docs/minimax-h3/api/minimax-h3-video-api) 与本地适配器；实际字段以已核验版本为准，更新前不自动探测账户或生成测试。
- 写作精简、按模型校验与素材分工参考 [Higgsfield 通用生成 skill](https://github.com/higgsfield-ai/skills/tree/main/higgsfield-generate)；未导入其默认模型、计费习惯或执行权限。
- 中文语速、Context-IR 保真、声线稳定性等仍以项目实际媒体为证；社区经验和建议不等于供应商保证。来源详见 [原调研记录](../../调研/H3技能调研记录.md) 及各参考页。
