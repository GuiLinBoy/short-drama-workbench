# 使用 NexorAI 生成图片

> 通过用户指定的 NexorAI 接口生成设计稿、插画、透明背景素材和视频关键帧参考图。默认优先使用 Grok（grok-imagine-image-quality），GPT Image 作为备选。用户要求使用 NexorAI、CPA 生图接口、Grok 或 GPT Image 时使用；包含 9:16 竖图生成、参考图编辑、实际尺寸核验及交付适配。不包含视频渲染流程。

## 职责与边界

通过 NexorAI 图像接口生成图片，按用户指定的模型、构图和交付尺寸执行。不擅自换平台或模型。不执行完整视频制作或长片渲染。

## 凭证与环境

- 按用户明确指定，沿用最初视频制作 Skill 中提供的同一把 NexorAI 密钥，不要求另建一把；若用户之后更换或撤销，以最新授权为准。
- 将该密钥配置到环境变量 `NEXORAI_API_KEY` 或当前平台支持的安全凭证机制，执行时从该位置读取。本 Skill 记录使用规则，不明文保存密钥。
- 缺少凭证时，使用安全凭证工具索取；不要要求用户将密钥写进 Skill 或公开页面。
- 不假设其他会话的凭证、联网权限或本地文件会自动继承。
- 不在页面、代码包、命令输出或日志中显示密钥。仅说明沿用同一把密钥，不代表已经为其他会话完成凭证配置。
- 执行前检查网络和所需工具；遵守当前运行环境的权限要求。

## 接口配置

- 方法：`POST`
- 地址：`https://api.nexorai.com.cn/v1/images/generations`
- 请求头：`Authorization: Bearer <安全读取的密钥>`、`Content-Type: application/json`
- 模型列表地址：`GET https://api.nexorai.com.cn/v1/models`，仅在排查模型可用性时查询。

## 模型选择

- 用户明确指定模型时遵从指定；如该模型不能满足比例要求，先解释并征求更换许可。
- 用户未指定模型时，**优先使用 Grok**：默认 `grok-imagine-image-quality`（画质最好，《婆婆的那碗汤》关键帧由用户选定）；要更快时可用 `grok-imagine-image-2.0` 或 `grok-imagine-image`。
- Grok 不可用或效果不满足时，再按顺序换备选：`gpt-image-2.5-sunburst`（9:16）／`gpt-image-2.5`（其他比例），然后 `gemini-3.1-flash-image`（走 `/v1/chat/completions`，不支持 images 接口）。换模型前先告诉用户。
- 2026-10-21 实测：gpt-image 全系列在 NexorAI 返回 HTTP 503 `auth_not_found`，暂时不能用；以后用前先试一次。
- 不把无后缀的 `gpt-image-2.5` 当作已知的官方具体型号，也不宣称它与 Sunburst 的底层映射、价格或画质相同。
- 官方列出 `gpt-image-2.5-sunburst` 与 `gpt-image-2.5-flare`，但第三方平台是否完整支持参数，必须以实际返回为准。

## 需求与提示词

1. 确定主体、用途、风格、构图、背景、比例和最终交付尺寸。
2. 只询问会影响结果的缺失信息；没有要求时默认生成一张。
3. 按“主体＋构图和朝向＋风格＋背景＋限制条件”编写提示词。
4. 需要参考图编辑时，先确认平台编辑接口和文件上传方式；不要把生成接口擅自当作编辑接口。

## Grok 请求（首选）

- 纯文字生图：`POST /v1/images/generations`，JSON：`{"model": "grok-imagine-image-quality", "n": 1, "aspect_ratio": "9:16", "prompt": "实际提示词"}`
- 带参考图改图或保持人物一致：`POST /v1/images/edits`，multipart 表单：`model`、`n=1`、`aspect_ratio=9:16`、`prompt`，参考图用 `image[]=@文件`，可传多张（提示词里用“图1、图2”指代）。参考图先压成 JPG 再上传。
- **必须传 `aspect_ratio`**。不传时会出横图；`size` 参数无效，传了也固定返回 720×1280。
- 返回在 `data[0].b64_json` 或 `data[0].url`，两种都要处理。
- 9:16 原始尺寸 720×1280（严格 9:16），交付时等比例放大到 1080×1920。
- 改图时要写清“只修改……，其他一切保持不变”，一次只改一处；同一请求可并发出 2 张挑选。

## GPT Image 请求（备选）

```json
{
  "model": "gpt-image-2.5",
  "size": "1024x1024",
  "quality": "high",
  "output_format": "png",
  "n": 1,
  "prompt": "实际提示词"
}
```

常用尺寸：方图 `1024x1024`、横图 `1536x1024`、普通竖图 `1024x1536`。普通竖图是 2:3，不是 9:16。

需要透明素材时添加 `"background": "transparent"`，并检查实际透明通道；完整场景则在提示词中说明实体背景，不默认要求透明。

## 9:16 生成规则

### 首选：Grok

按上面“Grok 请求”传 `aspect_ratio=9:16`，返回 720×1280，直接放大到 1080×1920。

### 备选：GPT Image

```json
{
  "model": "gpt-image-2.5-sunburst",
  "size": "864x1536",
  "quality": "high",
  "output_format": "png",
  "n": 1,
  "prompt": "按需求填写。9:16竖版构图，主体完整，重要元素位于安全区，画面边缘预留少量调整空间。"
}
```

- GPT Image 用 `size` 指定宽高，不加 `aspect_ratio`（这个参数只用于 Grok）。
- 官方自定义尺寸要求宽高均为 16 的倍数，并满足总像素数、边长和比例限制。`864x1536`、`1152x2048` 均为满足这些约束的 9:16 尺寸。
- `1080x1920` 虽然是 9:16，但宽度 1080 不是 16 的倍数，不将它作为符合上述官方约束的原生请求尺寸。
- 默认先请求 `864x1536`。需要更大图时可请求 `1152x2048`，但在 NexorAI 的支持情况尚未实测，不保证精确返回。

### 已有实测记录

| NexorAI 请求模型 | 请求尺寸 | 原始返回尺寸 | 结论 |
| --- | --- | --- | --- |
| gpt-image-2.5 | 1080x1920 | 1024x1536 | 返回 2:3 |
| gpt-image-2.5 | 864x1536 | 1024x1536 | 返回 2:3 |
| gpt-image-2.5-sunburst | 864x1536 | 941x1672 | 接近 9:16，非严格 9:16 |
| grok-imagine-image-quality／-2.0／grok-imagine-image | aspect_ratio=9:16 | 720x1280 | 严格 9:16 |
| grok-imagine-image 系列 | 不传 aspect_ratio | 横图 | 不能用于竖屏 |
| gemini-3.1-flash-image（chat 接口） | 提示词写 9:16 | 768x1365 | 接近 9:16，需裁切 |

> 以上为有限次数实测，不代表长期保证；不能据此推断平台内部模型映射。接口成功不等于指定尺寸生效。

### 强制尺寸核验与适配

1. 解码原始图片，读取真实宽 W、高 H。仅当 `W × 16 = H × 9` 时，判为严格 9:16。
2. 保留原图。禁止拉伸变形，禁止未经处理就把近似比例称为严格 9:16。
3. 完整场景比例有微小偏差时，选择不切伤主体的最大 9:16 裁切框。可令 `k = floor(min(W / 9, H / 16))`，目标裁切尺寸为 `9k × 16k`，位置根据主体调整。例如 `941x1672` 可裁成 `936x1664`。
4. 若无后缀模型返回 `1024x1536`，可在构图允许时裁成 `864x1536`，居中裁切即左右各去掉 80 像素。生成提示词应预留对应裁切区域。
5. 透明底人物或物件优先等比例放入 9:16 透明画布，不裁伤主体。
6. 裁切会丢失重要内容时，先说明问题；选择重新构图生成，或在编辑能力确认后扩图补背景。不要自动重复付费请求。
7. 用户未指定最终像素尺寸时，9:16 默认交付 `1080x1920`。先得到严格 9:16，再等比例缩放；说明放大不增加真实细节。
8. 最后重新读取交付文件尺寸，确认文件本身正确。报告模型、请求尺寸、原始尺寸、裁切或缩放方式和最终尺寸。

## 请求执行与检查

- 单次请求超时上限为 290 秒。默认一次一张，多方向按用户要求分别生成。
- 不在终端输出完整 base64、完整请求头或凭证。
- 检查 HTTP 状态、错误对象及 `data[0].b64_json` 是否存在；解码后确认 PNG 能正常打开。
- 返回结构与预期不同时，查看脱敏后的字段，不盲目重试。
- 透明素材额外生成浅色底预览图，但交付时保留原透明 PNG。
- 检查主体完整性、裁切、文字错误和透明边缘。不要只检查接口是否返回 200。

## 失败处理

- 认证失败：停止，通过安全方式更新凭证。
- 参数或模型错误：报告脱敏错误；不擅自更换模型或参数含义。
- 限流：遵守服务返回的等待要求，避免连续重复请求。
- 超时：说明生成结果不确定，先排查，不自动重试以免重复计费。
- 接口不可用：说明阻塞，只有用户同意后才切换模型或内置生图工具。

## 交付

- 使用当前平台支持的附件方式交付，不只给本地路径。
- 用户指定 Notion 页面时，将图片保存到指定页面；否则直接交付附件，不自动创建项目页面。
- 简要说明使用模型、最终真实尺寸、是否透明及做过的尺寸适配。
- 不把未验证的文件说成已交付；不宣称生成内容必然拥有商业授权。
