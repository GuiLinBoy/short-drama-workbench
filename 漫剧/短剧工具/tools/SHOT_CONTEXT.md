# 每段制作前的状态读取与衔接核对

本要求适用于全部作品。主执行者开始或恢复一个片段、修改提示词、提交生成前，读取本作品当前状态；聊天印象、旧交接和预计画面不能代替实际素材。用户审核仍在原有画布节点，内部核对不新建用户确认项。

## 读取当前事实

```powershell
python -I -X utf8 tools/shot_context.py --project <作品绝对目录> --clip EP001/Clip00002
```

只读输出当前配置、人物和音色登记的指纹、本段、同集相邻上下段、显式 `continue_from` 来源、相关提示词和素材的当前 SHA、实际结果审核以及尚未同步的采用。相邻关系按 `clips.json` 的成片顺序判定，不按生成完成顺序推测。首次制作也执行；新作品不继承旧片素材、状态或批准。

请求准备后，`h3_execution_checks.py` 自动重新读取同一状态。内部复核采用该次 `shotContext.fingerprint`，不得照抄已变化的快照。审核、素材、提示词或相邻关系变化后，旧复核失效；不因此撤销用户已通过的历史视频。

## 三项必须说明

1. **上段实际留下什么**：人物位置、姿态、朝向和画外人物；左右手与道具；门窗、家具、光线和时间；轴线、视线与景别；对白是否结束、声音基准及环境声。已有采用视频时查看真实画面/声音，引用该文件和通过记录。结果已通过但清单未采用，先同步；文件或记录失效先核对。
2. **本段怎么接**：开场怎样继承或改变上述状态，明确接法与省略动作。`continuous` 连续动作沿用 `continue_from`、真实尾帧、实际查看及 `set-continuity` 日志；`cut` 反打/切镜核对上段实际状态，但不强制上传尾帧；`independent` 转场/重新起幅须说明可独立制作的理由，缺上段视频时只能依据实际规划写 `planned`；`opening` 仅适用于本集无上段、无承接来源的开场。不能用独立起幅绕过已登记的连续承接。
3. **给下段留下什么**：人物/道具/空间/镜头/声音的片尾目标，下一段如何接或本集如何收束。尚未生成的本段只写 `target`，不能预标“实测完成”。读取下段规划；下段已先生成并采用时，反向查看它的真实开场。只在需要连续承接时留足稳定片尾，不强迫每段同样定格或上传尾帧。

五项状态无相关内容时说明具体原因，例如“此镜没有手持物，两人双手自然放下”，不以空白、“同上”或通用“通过”代替。生成后再用真实首中尾和声音验收目标是否实现；实际变化须回填采用及后续衔接，不能继续沿用预计状态。

## 并入既有内部复核

在现有 assessment 的 `checks.continuity_and_axis` 中填写 `handoff`。仍保留原有 `verdict`、`note`、`evidence`，不新增第七项或独立审核文件。

```json
{
  "contextFingerprint": "本次执行检查返回的 shotContext.fingerprint",
  "previous": [
    {
      "clip": "EP001/Clip00001",
      "basis": "actual",
      "reviewId": "实际已通过的来源视频审核ID",
      "state": {"people": "具体人物状态", "props": "具体道具状态", "space": "具体空间状态", "camera": "具体轴线视线", "sound": "具体声音状态"},
      "evidence": ["来源视频相对路径", "实际观察报告相对路径"]
    }
  ],
  "current": {
    "mode": "cut",
    "reason": "本段接法、保留与省略动作的具体理由",
    "state": {"people": "本段开场人物", "props": "本段开场道具", "space": "本段开场空间", "camera": "本段机位与视线", "sound": "本段发声与环境"},
    "evidence": ["本次实际请求的源提示词相对路径"]
  },
  "next": {
    "clip": "EP001/Clip00003",
    "basis": "target",
    "transition": "怎样交给下一段；集尾则说明收束",
    "state": {"people": "本段片尾人物目标", "props": "本段片尾道具目标", "space": "本段片尾空间目标", "camera": "片尾取景及下段视线", "sound": "对白收口和声音交接"},
    "evidence": ["本段源提示词相对路径", "下段提示词相对路径"]
  }
}
```

以上是字段示意，不是可直接签署的复核。`previous` 按快照 `upstream` 顺序覆盖相邻上段及额外承接来源；开场为 `[]`。独立制作、上段尚未就绪时用 `basis: planned`，证据含上段规划或 `clips.json`。集尾 `next.clip` 为 `null`。下段已采用时，`next` 增加其 `reviewId`，证据包含该实际视频。`current` 和 `next` 都引用本次实际源提示词。

缺文件、缺三项、缺任一状态维度、依据与采用版不符或快照过期，内部复核和正式提交均拒绝；先补缺项，不让用户额外确认技术报告。文件核对只能证明依据存在和版本一致，不能证明执行者真的看过或衔接一定自然，实际观察与专业判断仍须如实完成。

核对完成后，将模型需要的具体状态写入本段提交正文，并在本次请求附上必要参考。上述报告是执行者的工作证据，视频模型不会自动读取它，也不会记得前次生成。连续或反打都须在本段明确人物、说话人与音色、起始姿态/道具/空间及结尾目标；不能只留下“与上段一致”。
