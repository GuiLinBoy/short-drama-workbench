# H3提交前执行检查

2026-11-11起，`codex_cli.py` 的每次 `h3 submit --execute` 必须执行
`h3_execution_checks.require_execution_checks`。检查在读取凭据、访问服务和进入供应商提交程序前完成。
未配置声音方案不能成为有对白请求跳过检查的理由。

这是对现有规范的执行核对，不增加用户审核环节。总导演填写一次内部专业复核；用户继续在原有画布节点审核实际请求及结果。
不新增“技术审核通过”画布项，不让用户确认路径、SHA、登记或检查报告。

2026-11-15 补齐所有作品的 [首次开口音色收尾](VOICE_CLOSEOUT.md)。现有 `audio_binding` 组和提交入口同时核对：首次说话视频已通过后是否已提取、登记、提交声音节点，以及是否仍有已通过音色待同步采用。未完成先收尾；声音样本待用户确认时，仅可继续不依赖该人物音色的工作。首次定音请求必须证明该人物尚无通过的说话视频或音色登记；重复登记 bootstrap 不能绕过后续音色引用。样本审核必须为实际 `audio` 项，不能拿方案或视频审批冒充。

每段制作前按 [SHOT_CONTEXT.md](SHOT_CONTEXT.md) 读取当前状态。`analyze` 返回 `shotContext`；原有六项内部复核中的 `continuity_and_axis.handoff` 必须填写上段实际状态、本段接法、给下段留下什么，并绑定当前快照。上下段顺序、提示词、素材或相关审核变化使旧复核失效。缺项、缺实际依据、未同步采用或用预计状态冒充实测时拦截正式提交，不新增用户确认。

## 检查分工与依据

| 已有要求 | 自动检查/拦截 | 仍需总导演专业复核 |
|---|---|---|
| 模式、4—15整数秒、参数、六段/三段结构 | 非法参数、槽位混用、字段缺失或重复、实际正文超长 | 偏离标准版/768P/关闭Context-IR时核对现有明确取舍 |
| 真实参考与工具编号 | 文件、SHA、连续编号、附件职责标签是否引用、未映射标签、源稿与实际正文一致 | 实际看图；参考图只提供什么、组合图为何适用、视频自带声音的影响 |
| 说话人编号 | 首次开口顺序、段内固定、视觉主体和说话人对应、无台词主体不分配S编号 | 人物是否实际可见、脸嘴大小及清晰度、画外对白与听者 |
| 音色基准 | 只附本段说话人的音频；样本状态、对应人物的实际已审文件SHA、实测时长、精确首次定音例外 | 短样本及格式取舍；复用已确认音色，不重复要求用户确认同一样本 |
| 音频绑定 | 音频定义中的Subject/S编号、各对白阶段直接且唯一引用对应音频、仅参考声线的说明 | 参考声音与目标表演的适用性；不声称精确克隆或已排除乱语 |
| 原对白与固定声线 | 对照当前采用清单的人物/顺序/字词/标点；对照已采用或既有已审声线描述；禁止标签动作进入台词 | 未有机器可读基准时核对既有角色基准，不能任意改台词 |
| 台词、切镜、闭口 | 本段时间越界、倒序、重叠、切点错误、台词与闭口定格冲突、可识别听者及每句说完闭口 | 语速、交接、长句和跨镜风险；约3字/秒是保守建议，不冒充模型硬上限 |
| 台词后的补充发声说明 | 在当前对白结束到下一个时间块/镜头之间，拦截“再说一次”“按正常口语完整说一次”“对白时段是可用窗口”等已知歧义写法 | 只保留闭口和可见动作，必要语气放在本句对白前；此为写作约束，不证明已排除乱语或找到唯一原因 |
| 环境声、旁白与配乐 | 原生声音缺环境声、真正旁白混入H3、无对白却挂音色或缺少安静说明 | 声源是否具体合理；逐段配乐偏离默认方案的现有取舍 |
| 实际尾帧接续 | 连续片段附件、首个普通参考、两句已核对标记及日志、日志后改文、实际源视频与尾帧同属已通过结果 | 真正看见了哪些人/道具；画外人物回溯来源、视线轴线、门和抹布状态 |
| 风格、空间与镜头 | 对照已采用的全参考风格光线句；排除把首帧声线声明当风格基准的误判 | 人物大小距离、头顶两侧余量、纵深、同轴关系、相邻景别变化 |
| 动作复杂度 | 统计镜头、台词长度、语速及交接风险，未逐项处理风险不得内部签核 | 每镜动作意图/运镜、手部可达性、自然表演、素材覆盖和剪辑余量 |
| 可独立执行的正文 | 裸台词编号、成片绝对时间越界、制作/费用/审核流程文字、占位符 | 逐段读实际提交文本，排除模板遗留的语义冲突 |
| 当前版本及授权 | 同段更新候选出现即拦旧请求；请求/批次/attempt精确匹配；未采用的新编号不能执行 | 不把草稿当实际请求，不把历史通过当新版本通过 |
| 用户审核、预算、就绪和未知任务 | 继续执行现有画布、声音方案、预算/计费、次数、运行指纹与未知不重发检查 | 本次本地维护不产生消费授权或新的ready |
| 生成结果质量 | 提交前列出结果检查计划，明确尚不适用；已有解码/ASR工具用于生成后辅助 | 原音、音色、说话人和口型、真人细节、实际首中尾及规格，不能预先标通过 |

详细规则来源及SHA保存到检查报告的 `ruleSources`；本片 `作品约定.md` 也绑定到输入。
检查只接受当前采用的 `clips.json` 对应内容。拟11条素材等新计划应在原有方案通过并正式采用后再执行相应新编号，不额外增加确认。

## 离线使用

从工具根运行：

```powershell
python -I -X utf8 tools/h3_execution_checks.py --project "作品绝对路径" check --request "requests/实际请求.json" --output "reports/执行检查/本次自动检查.json"
python -I -X utf8 tools/h3_execution_checks.py --project "作品绝对路径" record --request "requests/实际请求.json" --assessments "reports/执行检查/总导演实际复核.json"
```

`check` 重新读取实际文件，显示自动错误、需要判断的风险和内部复核缺项。
`record` 只写 `reports/执行检查/`，不改用户审核、预算、就绪、共享清单或媒体。
自动错误不能豁免；风险必须逐项写明理由，不能通过清空warnings处理。

复核JSON须包含 `reviewer: "总导演"`、`checks` 和 `risks`。
`checks` 必须逐项填写 `reference_roles`、`framing_and_speakers`、`continuity_and_axis`、
`performance_and_pacing`、`spec_and_coverage`、`result_check_plan`。
每项包含 `verdict`（`pass` 或 `accepted-risk`）、具体 `note` 和作品内真实文件 `evidence` 数组。
`risks` 的键必须覆盖自动报告的每个风险code，值是具体取舍和限制。
不得自动填一批“通过”冒充实际复核，不得把尚未生成的视频或没有听辨的声音写成已验证。

每段还须在现有 `reference_roles`、`framing_and_speakers` 与 `continuity_and_axis` 内核对**独立请求是否交代完整**：只看本次实际提交正文和随附素材，能否知道每个可见人物是谁、谁发声及音色来源、谁闭口、开场人物/左右手/道具/空间状态和片尾目标。模型没有跨请求记忆，外部报告和上一轮附件不会自动传入下一次；依赖内容必须进入本段实际正文或本次附件并明确引用职责。此项并入原有六项复核，不新建用户审核节点，也不以一串上段编号代替具体描述。

## 复核复用与失效

2026-11-14 补充：正式提交会拒绝 project.json 的初始化待审状态和模型占位；从实际采用依据同步配置属于内部维护，不代表给新请求授权。规则指纹纳入镜头手册，检查器指纹纳入项目配置校验代码。修改规则后只为新请求补做内部复核，不重审已采用视频。

记录绑定实际请求SHA、源提示词、参考文件、声线基准、声音方案、上游素材、既有审核内容、适用规范及检查代码。
内容未变化时直接复用，不要求重复写记录；原画布项由待审变为通过本身不要求增加内部或用户审核。
内容或依据变化时旧内部记录失效，由总导演重新检查；用户只有在原有规则本来要求重审实际创作请求时才审核该请求。

运行就绪需要包含新增模块指纹。控制端使用 `codex_cli.runtime_pin_paths(root)` 获取当前完整集合，
离线验证后刷新技术指纹；不得因此编造新的费用批准、增加额度或开启真实生成。

自动检查识别可确定的错误并要求专业复核留下当前依据，不能保证生成模型完全服从提示词，也不验证导演文字记录本身等同真实看图/听音。

## 生成后验收补充（2026-11-13，本片复盘）

继续使用原有结果检查和结果画布，不另设用户节点。每段只保留一份当前结果摘要：

- 对照实际发声时段查看说话者和听者；ASR核字不等于说话人识别、音色试听或逐音节口型检查。没听过就写“未听辨”，不能代填通过。
- 关键动作按“起始状态→执行过程→完成状态”核对。出门关门须看跨门槛、门扇合拢及切镜前的最后画面；抽样接近切点仍不确定时，只补查该区间逐帧，不能用关门音或下一镜推定门已关严。
- 同一段既有对白、多人走位、门或道具交互又切镜时，优先简化动作并给完成状态留时间。保留高密度方案须记录具体未保证项，不能用通用“accepted-risk”取代判断；“1—2镜”本身也不等于简单。
- 分开记录技术可用、创作偏差、用户接受。用户接受后同步采用清单，仍保留客观偏差，不把本段容忍项推广为后续默认。
- 返工先指明证据和要改变的条件；能在现有授权内本地修复的先评估，额外付费仍依原有实际请求确认。使用同一素材的格式转换或原样截帧不新增创作确认。

依据：`作品/借钱时才是一家人/reports/复盘.md`。2026-11-13新增的是尾随说明检查与具体结果验收项；原有13组检查及6项内部复核不是本次新建。
