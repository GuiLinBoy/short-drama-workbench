# Codex本地调度与制作入口

## 音色必须随首次说话片段收尾（2026-11-15）

所有作品执行 [声音阶段收尾](VOICE_CLOSEOUT.md)：接收到角色首次开口视频的真实画布通过记录后，同轮提取、核对、登记音色并送到该人物唯一声音节点。运行 `python -I -X utf8 tools/voice_lifecycle.py --project <作品绝对目录> --require prepared`；待用户试听期间可标“制作已收尾、等待声音确认”，不能标音色已采用。声音通过后同轮同步 `voices.json` 与本作品声音引用，运行 `--require confirmed` 核对。已有有效确认复用，不重复审核同一文件。

清单更新、工作区状态和画布均返回同一音色收尾待办。缺提取、缺登记、缺送审、声音已通过但采用未同步时先收尾；后续同角色视频必须实际附加已通过的 `reference_audio`。首次定音例外不得重复使用；缺配置也不跳过检查。新剧继承规则入口，不继承旧剧音色、批准或例外。本地收尾与检查不调用生成服务。

## 新建剧集继承现行规则（2026-11-14）

新作品和续作都先读共享 `OVERRIDES.md`。`codex_workflow.py init` 自动给作品 `AGENTS.md` 安装指向共享文件的入口，`codex_materials.py` 同样补齐入口；二者保留作品自定义指示。规则不复制到作品中，每次任务按阶段读取当前原文件。用户已确定默认一个主执行者贯穿制作，五岗规范及适用检查全部保留；用户另行要求协作时才使用下文会话登记功能。

单主执行者按职责使用原有字段归属、受控提交和验收工具。检查及证据并入既有报告，未完成不得标通过，不适用须说明理由；内部自检不冒称独立岗位复核。没有新增岗位启动确认、技术确认或重复内容确认。

手工建立 `project.json`、尚未登记工作区时，由主执行者运行 `python -I tools/project_rules.py --project <作品绝对目录> --install`。命令只连接现行规范，不创建审核、预算或媒体。省略 `--install` 可只读检查实际规则路径与 SHA。

默认参数按 `OVERRIDES.md` 和数据规范：原生 768P、Context-IR 关闭；不默认追加 480P 试片。人物、原话、音色素材、预算、审核、发布用途均取本作品证据；不从旧项目搬入。`make_sample_project.py`、dryrun 及《雪夜推门》固定验收配方只用于演示/测试，不是新作品生产模板。

H3 每次受控提交自动调用共享执行检查，规则更新使旧内部复核失效，由内部重核；不重审已采用视频。合成调用共享 `audio/assemble.py`，选曲和上传交付按共享 `skill/references/post-production.md` 调用 `audio/delivery_checks.py`。实际听看仍由原有验收完成，不能用文件或 ASR 检查代替。

下文带具体旧片、日期的限制和开发暂停记录仅描述当时状态；当前范围以本作品实际授权、任务与现行规范为准，不据此追加确认。

本入口替换制作侧的NexBot身份、scope和专用桥接依赖，复用已有生成、状态、计费和后期工具。它不启动模型或聊天；真实会话由获得用户授权的Codex应用控制端创建和协调。当前作品已准备为默认禁止真实网络操作，未安装付费就绪记录。

当前执行澄清：推理、派活和汇报直接在现有Codex会话进行。codex_cli.py是本地Python制作工具入口，不是Codex Agent CLI；制作路径不调用codex exec、claude等另一套模型进程。工具就绪与获批操作以作品实际approvals为准，开头“默认禁止”描述初始状态，不能替代当前状态核对。

## 使用入口

在工具根目录以Python的隔离模式运行：

~~~powershell
python -I tools/codex_workflow.py --project "<作品绝对路径>" status
python -I tools/codex_materials.py --project "<作品绝对路径>"
python -I tools/codex_workflow.py --project "<作品绝对路径>" index
python -I tools/run_codex_checks.py
~~~

init需要本作品现有project.json、授权和execution-limits，明确work-id、全部scene、total-ms和narration-limit。重复相同登记幂等，不覆盖不同工作区。真实作品不使用simulation；隔离演练必须标记simulation。导出启动说明不创建会话，已有说明被人工修改后不会静默覆盖。

全局调度和五岗启动材料保存到漫剧/调度和作品/协作/启动材料。各作品工作区、任务、会话映射和回执分别保存；全局索引是可重建的视图，不是预算或任务事实来源。所有共享制作清单仍只通过pipeline_state写入。

## 实际会话和最终回复

应用控制端根据真实create_thread结果构建就绪观察，字段为source=CODEX_APP_CREATE_THREAD、threadId、hostId、status=ready、simulation。仅用真实ID登记角色；pending、标题或UI控件ID不够。五岗ID不可复用；角色有running/unknown任务时不能直接替换会话，换岗保留旧映射历史。

task登记任务角色、提案种类、scene、输入相对路径、依赖和可选有限action，绑定当前会话。调度先选定稳定task-id；相同ID和说明的创建重试保持原状态，不重复建任务。start在锁内领取任务；重复领取不会再次执行。输入文件变更或依赖未完成会拒绝。任务只接收本作品输入，父目录、绝对路径和越界链接会被拒绝。

初始只读任务可用--prepare-before-thread在模型调用前固化ID和输入指纹，状态为awaiting_thread，threadId/hostId为空，不能start。用户批准后，把该任务ID和输入交给create_thread初始提示；控制端取得真实就绪观察后bind并attach，再登记start和最终结果。attach不启动模型。这样不用先发一轮无任务的问候，也不需要伪造会话ID或在模型读文件后才计算输入版本。

完成观察由控制端读取实际最终回复后构建，字段为：

~~~text
source: CODEX_APP_FINAL_RESPONSE
threadId, hostId, turnId: 实际应用观察到的标识
taskId: 该次派活的本地任务ID
inputsSha256: 任务inputs映射的规范JSON SHA256
status: completed
finalSha256: 最终回复原文的UTF8 SHA256
simulation: 必须与工作区和任务一致
~~~

这些是本地标准化字段，不冒充应用工具的原生DTO。必须由可信控制端从真实结果建立关联；收到worker自报的状态或turnId不能直接当观察。现已通过五个真实只读会话验证应用ID、turn、最终回复和本地回执的关联；后续生产仍须核对。本地校验和不是签名，不能防御同用户任意改写。

实际应用接通后，codex_app_receipts.py接纳read_thread的完整原始最终回复，核对真实thread/host/turn、completed状态、唯一final_answer和原文SHA；不修补JSON，不从紧凑wait_threads摘要推测字段。已观察到紧凑摘要会截短JSON，故它仅用于状态等待，不能作为回执原文。接纳入口本身不调用模型。

complete校验会话/任务/输入指纹、最终JSON、角色归属和本地素材证据，再独占创建回执。旧report不能换内容或归属；截断/损坏记录拒绝且不删除。回执写入与任务状态更新间中断，可以按同一真实观察幂等接续；不会重新调用模型。recover把仍在running的本地任务标为unknown；不会自动重启任务或重新提交媒体。

如果本地完成回执已经保存、只有任务状态尚未更新，可以使用reconcile核对现存回执、输入和产物后恢复完成状态。该命令不执行工具；无回执、错归属或产物已变更时拒绝，不凭口头说明补造完成记录。

通用work-report只提供summary、artifacts和needsUser。产物只能引用本岗位的协作/提案或本任务reports目录及当前SHA；不能声明授权、其他岗位或共享清单是自己的产物。script/visual-prompt/continuity/voice-range/technical-review复用原数据校验；场景列表与总时长从工作区传入，不再把所有作品固定成三个片段。

## 工具和制作动作

codex_cli.py以--project-scope接收已登记作品，复用解释器/FFmpeg固定摘要、受控子进程、输出脱敏、本机ASR设置及现有媒体限额。离线命令不读取服务凭据，禁止Python网络连接；这只约束可信工具路径，不是OS沙箱，也不承诺任意子程序被网络隔离。

真实网络操作必须有独立的codex-live-ready及记录实际用户批准的授权引用，匹配作品、操作和当前预算、限额、解释器清单及执行代码摘要；空文件、旧NexBot就绪文件或仅--execute都不能放行。当前不提供“运行测试就自动打开付费”的命令。使用者不能伪造用户批准记录。NexorAI对话/看图另需正确计数，不通过此媒体入口自动获取额度。

预算摘要固定批次的额度和授权字段，允许used、_operations及pending_settlements正常记账；used必须与操作流水之和一致，不能通过清零继续。额度或其他策略字段变化仍拒绝。真实submit在读取凭据前检查对应请求的warnings，存在未解决警告就停止。wait的子查询沿用Codex入口，损坏的工作区不回退旧入口。

codex_jobs.py只适配《雪夜推门》现有三段24秒有限配方，不声称已经实现任意剧本的全部制作动作。通用作品、会话、任务与回执层可用于其他作品；不同长度的配方仍需按新作品计划明确配置和验证。

本试片的plan-register要求三段真实编剧回执与准备分镜的时长、旁白和镜头visual原文一致，且任务输入包含两份计划及全部提示词的指纹。如果编剧要改剧情或提示词，先明确新版本和审核，再更新对应配方输入；不能收了新提案却偷偷继续使用旧准备材料。

新版本通过任务的plans字段明确选择assets/clips两份JSON，路径必须属于本作品提案、列入该任务输入指纹，只允许编剧的plan-register使用。未选择时仍用原准备文件。新路径传给原配方的plan_files钩子，不覆盖旧准备文件、不自动选择最新候选；三段真实编剧回执仍须与所选版本逐项一致。

登记时从获审提示词派生独立运行副本，真实尾帧承接修改运行副本，保留岗位原提案和已接收输入指纹。4秒最小验证必须显式依赖摄影实际交付的专用4秒提示词，禁止直接复用8秒正式稿。

正式有对白的段落可派生声线绑定副本，明确引用真实音色参考并保留既定台词与时段；无对白段不附音色音频。真实技术审核由控制端把本任务实际输入文件的证据登记表传给应用回报接收器，仍核对文件SHA和reviewTaskId，不接受模型自报证据。

编剧也可在一个真实work-report任务中交付三份.script.json及所选clips计划，均列为实际文件产物并校验SHA；控制端从该唯一真实回执读取并验证三段数据。不会把同一turn伪装成三次模型任务，不能混入另一份编剧bundle或模拟回执。

导出新作品材料只初始化尚不存在的全局调度规则与当前交接，保留已运行作品的调度状态。每作品岗位材料仍拒绝覆盖人工修改。

动作必须属于预先登记的本岗位任务，不能传任意shell、argv或输出路径。需要提案的动作只接受该任务显式依赖的真实完成回执，拒绝模拟回执。完整工具结果和日志写入本机reports，聊天回传只含任务状态和证据位置/摘要。LOCAL_TOOL_COMPLETED只证明本机动作完成，不等于生成质量、真实看图或用户成片批准。

有限配方可复用，但不要求为每个维护续接新建配方。岗位会话可在总导演明确派发、既有批准操作/输入/批次/额度内直接调用codex_cli的制作动作，保存实际应用commandExecution状态、进程退出码、原生provider state、计费和输出SHA。模型work-report不能冒充LOCAL_TOOL_COMPLETED；控制端从实际工具证据核验结果。被维护中断的旧job只在确认原进程退出后单独记录unknown，不重跑整批；已有provider attempt仅query，未提交的条目经核对后首次submit。

必要的纯本地FFmpeg/FFprobe后处理可由岗位会话直接调用既有Runner.media所核对的固定二进制及净化环境，不为单个动作新增CLI。只允许本作品本地源和新版本输出、-n不覆盖，记录源/结果SHA、参数和实际测量；不允许URL输入、服务请求绕过codex_cli或伪造时长。需修正供应商时长/画幅偏差时，由导演依据真实对白/动作/尾帧证据选择处理，处理后重新识别、probe及查看，保留原始交付，不放宽创作或验收规格。

2026-11-07的角色图DNS失败仍保留unknown。用户只批准同源角色图attempt002一次精确例外，原6张总上限和旧占用不变。入口固定批准记录SHA、原unknown状态SHA、请求SHA、模型/n/画幅/目标/批次和新attempt；其他未知重试及attempt003仍拒绝。这不是通用恢复开关。
